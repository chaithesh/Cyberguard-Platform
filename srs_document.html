1. Introduction

1.1 Purpose

This Software Requirements Specification (SRS) document provides a rigorous, complete description of the functional, non-functional, interface, and behavioral requirements for the CyberGuard Cybersecurity Platform. It defines the operational criteria for multi-vector phishing detection, algorithmic threat scoring, Explainable AI (XAI) feature attributions, and Security Operations Center (SOC) incident reporting.

1.2 Document Conventions

This document conforms to the IEEE Std 830-1998 specification format. Requirements are uniquely labeled with identifiers (e.g., [FR-URL-01] for Functional Requirements, [NFR-PERF-01] for Non-Functional Requirements). The keywords SHALL, MUST, and SHOULD convey mandatory and recommended design specifications respectively.

1.3 Intended Audience

This document is intended for project evaluators, software engineers, cybersecurity researchers, and SOC administrators who require an authoritative specification of the platform's architectural mechanics and algorithmic dependencies.

1.4 Project Scope

CyberGuard is an integrated, client-side, edge-computing cyber defense platform. It supersedes traditional, slow static URL blacklists by delivering real-time, zero-day threat analysis across five interaction vectors: Web URLs & DOM structures, Email messages & authentication headers, SMS lures (SMiShing), Voice calls (Vishing), and Digital images/QR codes (Quishing).

2. Overall Description

2.1 Product Perspective

CyberGuard operates as a self-contained Single Page Application (SPA) supported by a lightweight, native Node.js HTTP server. The system adopts a Zero-Knowledge / Edge-First architecture: all computations, heuristic calculations, and data stores operate inside the client browser environment, preventing sensitive corporate emails and personal phone records from leaking to external cloud servers.

2.2 Product Functions

  • Real-time lexical domain parsing, typosquatting calculation, and Shannon entropy analysis.
  • Verification of cryptographic email headers (SPF, DKIM, DMARC) and Return-Path envelope validation.
  • Natural Language Processing (NLP) detection of psychological urgency and CEO fraud lures.
  • Telephony reverse caller ID lookup and STIR/SHAKEN protocol spoofing telemetry.
  • HTML5 Canvas Error Level Analysis (ELA) for image compression tampering and QR decoding.
  • SHAP-style Explainable AI (XAI) feature attribution and adversarial perturbation generation.
  • Browser-compiled YARA rule sandbox for custom threat hunting.
  • Local persistence via the Web Storage API and formal SOC report export (JSON/PDF).

2.3 User Classes and Characteristics

User Class Description & Technical Proficiency
SOC Security Analyst Advanced technical proficiency; utilizes YARA rule compiler, IoC search engine, ELA heatmaps, and exports JSON SIEM telemetry.
General End User / Employee Basic technical proficiency; scans suspicious links, checks SMS/phone lures, and completes awareness training simulations.
Academic / System Auditor Evaluates compliance with cryptographic RFC standards, XAI transparency, and data privacy safeguards.

2.4 Operating Environment

  • Server Environment: Node.js runtime environment (v16.0.0 or higher) running native HTTP services.
  • Client Environment: Any modern standards-compliant web browser supporting ECMAScript 2022+ modules and HTML5 Canvas (Google Chrome 90+, Microsoft Edge 90+, Firefox 88+, Safari 14+).
  • Operating System: Platform-independent (Windows 10/11, macOS, Linux).

2.5 Design & Implementation Constraints

  • Zero External Cloud Database: To preserve user confidentiality, the application shall not transmit user payloads to external database engines (e.g., MySQL, MongoDB).
  • Storage Constraint: Browser localStorage is capped at 5 MB per origin. Scan history is constrained to the 50 most recent records.
  • Browser Sandbox: Raw TCP/UDP socket calls are constrained by browser security models; live WHOIS and telco tokens are simulated algorithmically.

3. Specific System Features & Functional Requirements

3.1 Feature 1: URL & DOM Lexical Heuristic Analyzer

[FR-URL-01] The system SHALL parse input URLs into protocol, hostname, path, and query tokens using WHATWG standards.
[FR-URL-02] The system SHALL calculate the Levenshtein Distance between the input domain and 28 monitored target brands, assigning a +45 threat penalty when edit distance is between 1 and 2.
[FR-URL-03] The system SHALL compute Shannon Entropy on the domain string, assigning an +18 threat penalty for entropy values exceeding 3.8.
[FR-URL-04] The system SHALL flag raw IPv4 host addresses (+35 penalty) and Punycode xn-- homograph prefixes (+40 penalty).
[FR-URL-05] The system SHALL normalize cumulative scores between 0 and 100, assigning visual risk ratings: SAFE (0–34), WARNING (35–69), and DANGER (70–100).

3.2 Feature 2: Email Authentication & Psychological NLP Inspector

[FR-EML-01] The system SHALL parse RFC 822 email headers and evaluate SPF, DKIM, and DMARC verification statuses.
[FR-EML-02] The system SHALL detect envelope spoofing by verifying alignment between the visible From: domain and the underlying Return-Path: domain.
[FR-EML-03] The system SHALL apply NLP regular expression heuristics to detect high-urgency keywords, wire transfer requests, and executive gift card fraud.
[FR-EML-04] The system SHALL identify dangerous file attachment extensions, including double extensions (e.g., .pdf.exe) and macro-enabled documents (.docm, .xlsm).

3.3 Feature 3: SMS SMiShing Detection Module

[FR-SMS-01] The system SHALL scan text messages for common smishing lures: postal re-delivery fees (USPS, FedEx, DHL), bank lockouts, and tax refund baits.
[FR-SMS-02] The system SHALL extract shortened URLs (e.g., bit.ly, tinyurl.com) and pipe them directly into the URL heuristic engine.
[FR-SMS-03] The system SHALL flag unverified international sender prefixes and spoofed alphanumeric sender IDs.

3.4 Feature 4: Telephony Vishing & Reverse Caller ID Engine

[FR-VSH-01] The system SHALL execute reverse lookups against a built-in directory of known robocall scams (IRS fraud, tech support refund scams).
[FR-VSH-02] The system SHALL evaluate telephony carrier types and assign risk flags to anonymous VoIP virtual lines (Twilio, Bandwidth).
[FR-VSH-03] The system SHALL allow users to register, save, and update custom verified caller identities into browser localStorage.

3.5 Feature 5: Image Forensics & Canvas Error Level Analysis (ELA)

[FR-IMG-01] The system SHALL extract image EXIF metadata tags to detect manipulation software (Photoshop, GIMP) and AI generation tags (Midjourney, Stable Diffusion).
[FR-IMG-02] The system SHALL render an Error Level Analysis (ELA) compression variance heatmap on an HTML5 <canvas> to highlight spliced text and logos.
[FR-IMG-03] The system SHALL decode QR code matrix payloads (Quishing) and evaluate destination link safety prior to redirection.

3.6 Feature 6: Explainable Artificial Intelligence (XAI) & Adversarial Lab

[FR-XAI-01] The system SHALL compute class probabilities: Legitimate %, Suspicious %, and Phishing %.
[FR-XAI-02] The system SHALL compute SHAP-style positive and negative feature attributions explaining the numerical impact of each detected risk factor.
[FR-XAI-03] The system SHALL generate adversarial URL mutations (homoglyphs, hex encoding, subdomain padding) to benchmark model resilience.

3.7 Feature 7: In-Browser YARA Rule Threat Hunting Sandbox

[FR-YAR-01] The system SHALL compile YARA-style syntax (rule, meta, strings, condition) directly inside the browser using regular expression parsing.
[FR-YAR-02] The system SHALL evaluate compiled signatures against raw string payloads and display matched variables and severity indicators.
[FR-YAR-03] The system SHALL provide a searchable Indicators of Compromise (IoC) table for known malicious file hashes, C2 IP addresses, and phishing domains.

3.8 Feature 8: SOC Incident Reporting & JSON/PDF Export

[FR-REP-01] The system SHALL compile real-time scan findings into a standardized Security Incident Report.
[FR-REP-02] The system SHALL provide a one-click Download JSON export button to serialize telemetry for SIEM platforms (Splunk, Elastic).
[FR-REP-03] The system SHALL provide a formatted Print / Export PDF stylesheet for formal audit documentation.

4. External Interface Requirements

  • Visual Analytics: Interactive Chart.js donut and bar charts for live risk distribution visualization.

  • Navigation: Tab-based single-page routing without full page refreshes.

  • Hardware acceleration for HTML5 Canvas 2D image pixel rendering.

5. Non-Functional Requirements

5.1 Performance Requirements

[NFR-PERF-01] The system SHALL complete lexical URL parsing and Levenshtein distance calculations in less than 50 milliseconds.
[NFR-PERF-02] The HTML5 Canvas Error Level Analysis SHALL render visual heatmaps within 500 milliseconds for images up to 4 MB.
[NFR-PERF-03] The application SHALL achieve initial cold-load boot times of under 1.5 seconds on standard consumer hardware.

5.2 Safety & Zero-Knowledge Privacy Requirements

[NFR-SEC-01] The system SHALL execute all detection algorithms strictly within the local client sandbox. User emails, phone logs, and URLs SHALL NOT be transmitted to any external third-party servers.
[NFR-SEC-02] The local server SHALL enforce path sanitization using path.normalize() to block path traversal directory exploits (../).

5.3 Software Quality Attributes

  • Portability: Runs seamlessly across Windows, macOS, and Linux without native binary dependencies.
  • Maintainability: Clean decoupling between UI presentation components (js/components/) and core algorithmic engines (js/engine/).
  • Usability: Provides self-explanatory risk scores and transparent Explainable AI cards suitable for both technical analysts and laypersons.
